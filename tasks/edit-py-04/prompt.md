# edit-py-04: 精准修复复杂结算与退货引擎中的单处分支条件

## 背景与需求

当前仓库是一个电商订单结算、分仓拆单与分段退货对账引擎（包含 `src/models.py`、`src/policies.py`、`src/settlement_engine.py`）。近期财务对账发现：在部分复杂订单执行多次分段退货时，退货应付金额与“满减促销退回（Clawback）”判定偶尔与业务规范不一致。

### 相关业务规范（结算与退货一致原则）

1. **结算折扣顺序**：
   - 订单行先扣除捆绑套装折扣（`BundleRule`）得到折后价，再对 `member_eligible=True` 的商品按会员等级扣除会员折扣，得到每行的会员折后净额（`after_member_cents`）。
2. **全店满减（`PromoRule`）门槛与资格**：
   - 全店满减仅统计 `promo_eligible=True` 的商品，且以这些商品的**捆绑与会员折后净额汇总值**（即 `after_member_cents` 之和，不含税费与运费）作为门槛判定口径。
   - 当上述合格汇总金额 **大于或等于（`>=`）** `promo_rule.threshold_cents` 时，订单满足满减门槛，获得 `promo_rule.discount_cents` 优惠（按各合格行 `after_member_cents` 比例以最大余数法分摊；不可超过合格行总额）。
3. **满减退回（`clawback_on_breach=True`）规则**：
   - 当订单享受了满减优惠且 `promo_rule.clawback_on_breach=True` 时，每次发生退货扣减对应商品数量后，需重新评估**剩余未退货商品**是否仍满足该满减门槛（同样仅统计 `promo_eligible=True` 且按 `after_member_cents` 口径，与原单门槛判定 `>= threshold_cents` 保持一致）。
   - 若此前尚未追回满减优惠，且本次退货后剩余合格金额**严格低于**门槛（即不再满足 `>= threshold_cents`），则本次退货须触发一次性满减追回：追回金额等于剩余未退货合格商品原本分摊到的未退满减优惠总额，从本次商品退货款中扣除，并将剩余各行的可退货基准恢复为追回后的真实剩余应付额（不包含已失效的满减）。
   - 若本次退货后剩余合格金额仍满足门槛（含恰好等于 `threshold_cents`），不得触发追回；一旦已触发追回，后续再次退货不得重复追回。
4. **对账守恒**：
   - 全单所有商品分多次退完全部数量时（在无额外运费不可退等情况下，对仅退商品与税款场景），累计退回金额之和必须严格等于原实付商品与税款总额，不得出现 1 分钱偏差。
