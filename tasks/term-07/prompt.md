# term-07: 按清单还原指定版本的发布文件树

## 背景与需求
澄湾灯塔（harborlight）的发布目录被打成了多份 `tar.gz` 和 `zip`。这些包来自不同版本，有的是正式包，有的是同版本镜像，有的是超过目标版本的草稿，还有一份没有列入清单的多余包。
请只根据 `bundles/catalog.json` 和其中点名的归档，还原**目标版本**的文件树，写到工作目录的 `restore/`，并在工作目录根生成 `restore.sha256`。
判分只读取 `restore/` 里的常规文件和 `restore.sha256`，不检查 `bundles/`，也不要求删除这些归档。整个工作目录都不要创建符号链接。

## 输入
1. 清单文件是 `bundles/catalog.json`，UTF-8，结构如下：
   - `target_version`：目标版本，格式固定为 `MAJOR.MINOR.PATCH`，三段都是不含前导零的非负十进制整数（`0` 本身允许）。
   - `sources`：归档数组。每项有 `archive`（相对 `bundles/` 的文件名）、`version`（同上的三段版本，**以该字段为准，不要从文件名推断**）、`rank`（整数）、`strip_prefix`（要剥离的路径前缀，空字符串表示不剥离）。
2. `sources` 的数组顺序、归档内的时间戳、文件权限都不参与裁决。
3. `bundles/` 里可能有清单没有点名的归档，那些归档整份忽略。
4. `.tar.gz` 是 gzip 压缩的 tar，`.zip` 是 zip。成员名按 UTF-8 解释；含非 ASCII 的 zip 条目带有 UTF-8 标志。以归档里记录的原始成员名为准，再做下面的归一化。不要用会折叠 `..`、改写反斜杠，或把成员解压到归档外面的默认解压结果代替这个规则。
5. 归档里只有常规文件和目录。目录成员（tar 的目录类型，或名字以 `/` 结尾的成员）直接跳过。

## 哪些归档参与
只处理 `sources` 里版本**小于或等于** `target_version` 的归档。版本按三段整数比较：先比 MAJOR，再比 MINOR，再比 PATCH。例如 `1.10.0` 大于 `1.9.0`。不要按版本字符串比较。高于目标版本的归档整份不参与，哪怕它的 `rank` 更大。
本题清单里，同一个 `version` 的 `rank` 互不相同。

## 成员路径归一化
对每个常规文件成员，按顺序处理它的原始成员名：
1. 含 NUL 的成员名整条丢弃。
2. 把反斜杠全部替换成 `/`。
3. 按 `/` 切开，丢掉空段和 `.` 段。名字开头的 `/` 只会产生空段，丢掉即可，不要因此丢弃整条成员。
4. 若剩余段里还有 `..`，整条丢弃。不要把 `..` 折叠掉。例如 `a/../b.txt` 要丢弃，不能变成 `b.txt`；`a/c/../../d.txt` 也要丢弃。
5. 若任一段是 `__MACOSX`，或最后一段是 `.DS_Store`，丢弃。除此之外，以 `.` 开头的文件名要保留。
6. 剥离前缀。`strip_prefix` 为空则不剥离。否则按 `/` 切开成非空段（本题每一项都只有一段）。仅当第 5 步之后的路径正好以前缀各段开头时，去掉这一次；对不上就保持原样。前缀只去一次，不要循环去掉。例如前缀 `a` 作用于 `a/a/b.txt` 得到 `a/b.txt`，而不是 `b.txt`；前缀 `a` 不作用于 `b/c.txt`。
7. 去掉前缀后如果路径为空，丢弃。
得到的路径称为逻辑路径，段之间用 `/` 连接，大小写敏感。

## 单个归档内的投票
每个参与的归档对逻辑路径投票，规则如下：
1. 逻辑路径以大小写敏感的 `.tombstone` 结尾时，它是删除标记。目标路径是去掉这个后缀后的路径。标记本身不是还原文件，标记里的字节一律忽略。
2. 同一归档只要对目标路径 `P` 出现过 `P.tombstone`，该归档对 `P` 的投票就是删除，忽略同归档里 `P` 的文件内容。这与两个成员谁先谁后无关。
3. 没有删除标记时，同一逻辑路径出现多次，以归档内靠后的那个成员的字节为准。

## 跨归档冲突
对每一个目标路径，只看参与归档的投票：
1. 先取版本号最大的投票；版本相同再取 `rank` 整数值更大的投票。`rank` 不能跨版本压过更新的版本，也不能按十进制字符串的字典序比较。
2. `rank` 只用来打破同一路径、同一版本的平局。低 `rank` 归档里没有被更高投票盖掉的文件仍然要保留，不能把整份低 `rank` 归档丢掉。
3. 胜出的投票如果是删除，结果里就没有这个路径。如果是文件，原样采用它的字节：不改换行、不补换行、不删换行、不转编码。长度为 0 的文件也要写出来。

## 输出
1. 把每个胜出的文件写到 `restore/<逻辑路径>`。只创建需要的父目录。`restore/` 下不要多出别的常规文件，也不要写入删除标记。
2. 在工作目录根写入 `restore.sha256`，不要放进 `restore/`。
3. `restore.sha256` 是 UTF-8 文本，列出 `restore/` 下的每一个常规文件，且只能列出这些文件。每行格式为：

```
<64 位小写十六进制 SHA-256><两个空格><相对 restore/ 的路径>
```

   例如（格式示例，不是本题的真实摘要）：

```
abababababababababababababababababababababababababababababababab  dir/file name.txt
```

4. 路径使用 `/`，不以 `./` 或 `/` 开头，不加重引号，不加 `*`，也不使用反斜杠转义。路径里的空格原样保留。
5. SHA-256 针对文件的原始字节计算，不包含路径。
6. 行按路径的 Unicode 码点升序排列，不要按系统 locale 排序。每行以 LF 结束，文件最后一个字符是换行，中间不要空行。
7. 不要求保留权限位、所有者和时间戳。

## 如何自测
- 按上面的规则核对 `restore/` 的相对路径和原始字节，再核对 `restore.sha256` 的摘要、两个空格、排序和换行。
- 完成后可执行 `python3 litmus.py check`，确认工作目录里没有符号链接。
