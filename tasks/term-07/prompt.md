# term-07: 按清单还原指定版本的北港发布树

## 背景

工作目录里的 `bundles/` 是北港一次发布留下的归档和清单。清单里混有过期版本、写错的版本号、缺失的文件和重复条目。`ship/NOTES.md` 和 `scratch/` 是旧说明和某次错误预览，其中的比较方法、解压方式和文件名规则都不要采用。

请在工作目录根生成：

- 目录 `restore/`：还原后的文件树，相对路径与逻辑路径一致
- 文件 `restore.sha256`：这些文件的 SHA-256 清单

只使用 Python 3 标准库和常见 POSIX 命令。不要联网，不要创建符号链接，不要把 `scratch/` 里的文件抄进 `restore/`。

## 清单

`bundles/catalog.json` 是 UTF-8 JSON，文件开头可以有 UTF-8 BOM。读入前先去掉 BOM。

字段：

- `target_version`：目标版本，解析规则与下面的版本号相同
- `drop_suffixes`：字符串数组。逻辑路径只要以其中任一项结尾就丢弃
- `sources`：源数组。每一条单独判断，互不影响。同一归档可以出现多次，非法的那条跳过，合法的那条照常参加

一条 source 必须同时满足下面全部条件，否则整条跳过，不要因此中止：

- 它是 JSON 对象
- `version` 能按下面的规则解析，并且解析后的整数元组 **小于或等于** 目标版本。大于目标版本的源整条不参加
- `rank` 的 JSON 类型就是整数。布尔值、字符串、小数都不是整数（不能用“能当作整数”来判断）
- `archive` 是非空字符串，并且文件 `bundles/<archive>` 真实存在
- `encoding` 是 `utf-8`、`latin-1`、`cp437` 三者之一
- `strip_prefix` 是字符串，允许空字符串
- `archive` 以 `.zip` 或 `.tar.gz` 结尾

没有写进清单的归档不要读。清单点名但磁盘上没有的归档，跳过该条即可。

## 版本号

版本字符串必须正好是三段，用 `.` 分开。每一段都只含数字，并且除了段本身就是 `0` 以外不能有前导 0。`1.10`、`1.09.0`、`1.10.0-rc.1` 都非法。

比较时把三段转成整数元组，按数值比较。`1.9.0` 早于 `1.10.0`，`1.100.0` 晚于 `1.10.0`。不要按字符串比较。

## 读归档

压缩包内的目录项不要写成文件。不要跟随、不要物化符号链接或硬链接。

`.tar.gz`：用该条 source 的 `encoding`，并且 `errors="strict"` 打开。只收取普通文件（常规文件，且不是符号链接、不是硬链接）的全部字节。成员名以打开时得到的字符串为准，包含 pax 长文件名。字节里的 CR、LF 都原样保留，空文件也保留。

`.zip`：跳过目录项（目录标志，或名字以 `/` 结尾）。通用标志位的第 11 位（掩码 `0x800`）表示文件名已经是 UTF-8：

- 该位置位时，成员名用 `ZipInfo.filename` 的 Unicode 字符串，不要再编码转换
- 该位没有置位时，`ZipInfo.filename` 是用 cp437 解码出来的。先把它 `encode("cp437")` 得到原始字节，再用该条 source 的 `encoding` 做 strict 解码。任一步 `UnicodeError` 就跳过这一个成员。例如原始字节 `0xE9`，cp437 会显示成希腊字母 Θ，按 latin-1 解码才是 `é`

同名成员在同一个 zip 里可能出现多次。用对应的 `ZipInfo` 分别读取字节，不要只留第一次。同一个归档内、变成同一逻辑路径的正文，后出现的覆盖先出现的。

## 逻辑路径

对每个成员的原始名字按顺序处理，任一步失败就丢弃该成员：

1. 名字里含有 NUL 字符，丢弃
2. 把反斜杠换成 `/`
3. 丢掉空段和 `.` 段
4. 任何一段是 `..`，丢弃整个成员
5. 任何一段是 `__MACOSX`，丢弃整个成员
6. 最后一段是 `.DS_Store`，丢弃
7. 去掉前缀：把 `strip_prefix` 也按 `/` 拆段并丢掉空段和 `.`。前缀非空，且逻辑段以该前缀开头时，只去掉这一次。空前缀什么都不去掉。例如前缀 `a/b` 作用在 `a/b/a/b/c.txt` 上，结果是 `a/b/c.txt`，不是 `c.txt`。前缀 `pkg` 不匹配 `pkg2/...`
8. 去掉前缀后如果没有段了，丢弃
9. 拼回用 `/` 连接的逻辑路径。若它以 `drop_suffixes` 里的任一项结尾，丢弃

然后才识别删除标记：逻辑路径以 `.tombstone` 结尾时，表示本归档对“去掉这 11 个字符后的路径”投删除票。去掉后如果路径为空，忽略这个标记。删除标记是否排在正文前面都一样：同一归档里只要出现过删除票，该路径在本归档的投票就是删除，正文留不下来。先做第 9 步再识别删除标记，因此以 `drop_suffixes` 结尾的名字不会变成删除标记。

## 跨归档取舍

每个归档先得到一张投票表：逻辑路径对应正文字节，或对应删除。再在所有参加的源之间，对同一逻辑路径比较 `(版本元组, rank)`，数值更大的投票胜出。胜出的投票如果是删除，或者没有任何正文投票，该路径就不出现在结果里。

高版本或高 rank 只覆盖它投票过的路径。低版本归档里其余路径仍然保留。不要因为另一份归档更新，就把旧归档整包丢掉。

## 写出结果

`restore/` 下放上所有留下的文件，相对路径就是逻辑路径，文件字节与胜出的正文一致。不要在 `restore/` 里放符号链接，也不要多放文件。

`restore.sha256` 是 UTF-8 文本：

- 把逻辑路径按 Python 3 的普通字符串顺序排序（Unicode 码点顺序，不用 locale）
- 每一行是小写十六进制 SHA-256、两个空格、逻辑路径、换行 `LF`
- 最后一行末尾也要有换行
- 若一个文件都没有，该清单是 0 字节

摘要对文件原始字节计算，不把换行符先规范化。

## 如何自测

可以在本地用标准库按上述规则算出文件和清单，再与 `restore/`、`restore.sha256` 逐字节比较。也可以执行 `python3 litmus.py check`，它只检查工作目录里没有违规符号链接。
