# review-py-04: 滞期费改口径

## 背景

滞期费从「元」改成了「分」，调用点要一起改。请审查这次改动。

仓库根目录的 `patch.diff` 是待审查差异，其余文件是改动后的完整内容。行号一律按改动后的文件计算。

## 要求

找出这次改动引入的缺陷，写入工作目录根的 `review.json`。每条是一个对象：

```json
[{"file": "相对仓库根的路径", "line": 1, "category": "类别", "description": "一句话说明"}]
```

- `file` 使用正斜杠，不要加 `./`。
- `line` 是正整数，指到最能说明该缺陷的那一行。
- `category` 只能是：空指针、越界、资源泄漏、并发、注入、逻辑错误、性能。
- `description` 用一句话说明失败场景。
- 最多 10 条。漏掉真实缺陷算未通过；多写的条目不会抵消漏报。
- 不报告命名、排版、注释措辞这类风格问题。
- 只报告 `patch.diff` 里出现过的文件中的缺陷。
- 契约以改动后源码里的方法说明为准。

## 如何自测

执行 `python3 litmus.py check`。该命令只检查 JSON 结构，不判断对错。
