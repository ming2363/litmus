# 修复标签校验被近乎匹配的输入卡死

工单标签要用一个确定的规则判断合法或非法。当前实现对一小段几乎全是合法字符、末尾或长度差一点的输入会陷入极慢的匹配，正常长度的合法标签也不能立刻返回。

## 合法标签

`tags.LabelValidator.isValid(String label)`

- `label` 为 `null` 时抛出 `NullPointerException`。
- 其他情况只返回 `true` 或 `false`，不要抛出别的异常。
- 整串长度是 1 到 96。
- 由一段或多段组成，段之间用一个 `.` 分开。
- 每一段长度是 1 到 48，只含 `a` 到 `z` 和 `0` 到 `9`。
- 不能有空段，因此不能以 `.` 开头或结尾，也不能出现 `..`。
- 大写字母、下划线、空格和其他符号都不合法。

34 个 `a` 是合法标签。49 个 `a` 不合法，因为它超过了单段长度。`ab.` 重复 32 次再加 `ab` 的总长度是 98，也不合法。

对任意长度不超过 96 的字符串，无论它是否合法，校验都必须马上返回，不能随着长度急剧变慢。不要用会灾难性回溯的正则。

`tags.LabelIndex` 只保存合法标签。`add` 遇到非法标签抛出 `IllegalArgumentException`。`contains` 按原文字判断。`all` 返回按字典序排列的新列表。

只修改 `tags/` 下的 Java 源文件，不要改测试。
