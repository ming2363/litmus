# 平台观测、灰度控制与 FinOps 变更单 #CHG-903

请综合下方三项业务诉求及 `service_registry.json` 中的精准资产标识，从 `tools_schema.json` 的 26 个平台工具中选出最匹配的工具，**严格使用各参数 schema 允许的枚举值**完成配置。

## 诉求一：灰度放量控制
结账网关（`checkout-gateway`）当前正在其金丝雀区域开展灰度发布。值班团队反馈部分节点出现尾延迟抬头，需要**先把当前金丝雀发布冻结在现状以保留观测现场**——注意：**既不要回滚到上一版本，也不要全量晋升**；暂停原因归类为尾延迟回归排查，并保留 `15 分钟` 的指标观测窗口。

## 诉求二：新建延迟监控规则
同样针对结账网关及其主区域，此前尚未配置静态 P99 延迟规则。请**新建一条静态阈值告警规则**（不要使用动态基线异常检测，也不要修改已有规则）：
- 监控指标为 P99 毫秒延迟，统计窗口取 `15 分钟`；
- 当指标**严格大于** `450` 毫秒时触发；
- 故障等级定为二级重大故障（major），通知路由走核心 SRE 值班 PagerDuty。

## 诉求三：FinOps 预算预测预警
面向搜索聚合团队归属的成本中心，建立一条**按月末预测总支出（而非周消耗速率或季度承诺）**触发的预算预警规则（注意：只做预算通知预警，**不要施加硬限流封顶或申请扩容配额**）：
- 计费范围限定为**计算资源加上行出网流量**（不含存储或其他全量费用）；
- 预测达到预算的 `90%`（即整数 `90`）时触发；
- 通知频道发送至 FinOps 专用 Slack 告警频道。
