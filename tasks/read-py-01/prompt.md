# read-py-01: 泊位看板的最终处理函数

## 背景

`harborboard` 是内河码头的泊位看板。代码里没有启动端口的入口，路由全部写在源码中。

请判断：方法为 `GET`、路径恰好为 `/harbor/v2/berths/active` 的请求，最终执行的业务处理函数是哪一个。

## 判定规则

以 `harborboard.http.router.Router#resolve` 的源码为准：

1. 只认该方法实际 import 并使用的路由表，以及它调用的分发函数。没有被这条调用用到的登记表不算。
2. 方法名比较时忽略大小写，路径大小写敏感，且必须整段相等，不要自行补上或删掉末尾斜杠。
3. 在方法相同的登记项中，先找不含 `{参数}` 的字面路径。存在与请求路径完全相同的字面路径时，取登记顺序里的第一条，不再看模板。
4. 没有字面命中时，才在模板路径里选择静态段更多的一条；静态段数量相同则取登记顺序更靠前的一条。模板段形如 `{view}`，不能匹配空段。
5. 访问日志、响应头包装不算业务处理函数。答案是这条路径最终调用到的业务方法。
6. 方法写成 `包.模块.类名#方法名`。

## 答案

把下面结构写入工作目录根的 `answer.json`，不要增加字段，字符串不要带首尾空白：

```json
{"handler": "包.模块.类名#方法名"}
```

## 如何自测

执行 `python3 litmus.py check`。该命令只检查 JSON 结构，不判断对错。
