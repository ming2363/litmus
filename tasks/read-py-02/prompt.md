# read-py-02: 夜班封账事件的分发链

## 背景

夜班台账的对外事件名不会直接登记到处理函数上，中间经过线码和键折叠。

请给出对外事件名 `ledger.nightly.closed` 从入口到业务处理函数的调用链。

## 判定规则

1. 入口是 `nightledger.ingress.Ingress#accept`。它收到的就是这个对外事件名。
2. 调用链按运行时进入顺序书写，包含入口自身、入口直接调用的映射与查找方法，以及最终被调用的业务方法。
3. 不要把这些方法内部再次调用的私有加载函数、导入函数展开进去。
4. 方法写成 `模块.类名#方法名`。模块路径与源码包一致。
5. 业务方法是折叠之后实际调用的那个方法，不是名字相近的预览方法。

## 答案

写入工作目录根的 `answer.json`：

```json
{"event": "ledger.nightly.closed", "chain": ["模块.类名#方法名"]}
```

`event` 必须原样填写。`chain` 按调用顺序，不要多也不要少。

## 如何自测

执行 `python3 litmus.py check`。该命令只检查 JSON 结构，不判断对错。
