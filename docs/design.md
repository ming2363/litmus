# litmus 设计文档

> 状态：已确认方案，待拆实现计划
> 日期：2026-11-08

## 1. 目标

在任意 Agent 工具里（Codex、OpenCode、Claude Code 等），选中想测的模型，粘贴一段固定提示词。模型自己一题一题做完，最后输出一份**客观指标**报告。

- 只测用户指定的那个模型，不和其他模型比较，也不给"换 / 不换"的结论。结论由用户自己判断。
- 测的是"工具当前配置下的模型"：工具里选了哪个模型就测哪个，litmus 不改工具配置。
- 全部在本机运行，没有服务端。

## 2. 使用方式

1. 克隆本仓库，在仓库根目录用 Agent 工具打开会话，选好模型。
2. 粘贴提示词：

```
你正在参加 litmus 编程能力测评。请在本仓库根目录执行
python3 litmus.py start
然后严格按命令输出的指示一题一题做下去，中途不要停下来问我，
直到出现 ALL DONE，最后把 python3 litmus.py report 的输出原样给我。
```

3. 等它跑完，拿到分数表。报告同时写入 `reports/` 目录，**以文件为准**。

快速模式：提示词里换成 `python3 litmus.py start --quick`，每个维度只抽 3 题。

## 3. 运行流程

```
start ──► next ──► 模型在工作目录做题 ──► submit ──► next ──► … ──► ALL DONE ──► report
            ▲                                 │
            └──────── 中断后说"继续" ─────────┘（状态文件断点续跑）
```

由脚本 `litmus.py` 控制节奏，模型只负责做题：

| 命令 | 作用 |
|---|---|
| `start [--quick] [--new]` | 检查环境，新建一次测评（run），输出做题规则。已有未完成的测评时默认续跑，`--new` 强制新开 |
| `next` | 发下一题：把题目复制到独立工作目录，输出题面和工作目录路径。当前题还没提交时，重复输出当前题，不跳题 |
| `submit` | 提交当前题：脚本当场判分、记录耗时，只回复"已提交"，**不透露对错**。每题只能提交一次 |
| `skip` | 放弃当前题，按不通过计分 |
| `status` | 查看进度 |
| `report` | 汇总成绩，输出到终端并写入 `reports/<日期>-<模型>.md` |

出题人用的命令（做题模型用不到）：

| 命令 | 作用 |
|---|---|
| `keygen` | 生成密钥，写到 `~/.litmus/key` |
| `seal` / `unseal` | 加密 / 解密题目的隐藏部分 |
| `selftest` | 逐题自检：起始代码必须**不通过**隐藏测试，参考答案必须**全部通过**。不满足的题不能入库 |

## 4. 防作弊与测量可信度

| 风险 | 结构上的处理 |
|---|---|
| 模型自己判自己 | 判分完全由脚本执行，不经过模型 |
| 模型偷看答案 | 隐藏测试、参考答案、标准答案统一加密成 `hidden.enc`，判分时解密到临时目录，用完删除。密钥只在 `~/.litmus/key`，不进仓库 |
| 公开仓库被爬进训练数据 | 题面明文公开没关系，只看题面学不到答案；能让模型背出答案的测试和参考解都是密文 |
| 反复试错刷分 | 每题只能提交一次，提交后不反馈对错 |
| 篡改判分脚本或测试 | `start` 时记录仓库 HEAD 提交号。`submit` / `report` 时校验 `litmus.py`、`litmus/`、`tasks/` 和 HEAD 一致，且 HEAD 没变。不一致则整次成绩标为**无效** |
| 仓库里的 AGENTS.md / CLAUDE.md / GEMINI.md 被工具自动加载，干扰做题 | 仓库根目录及各级目录**禁止**出现这类文件。`selftest` 检查到就报错 |
| 被测工具把任务外派给别的模型（如 ai-relay 自动模式） | `start` 检测本机 ai-relay 模式，不是 `off` 就拒绝开始，并提示怎么关闭 |
| 只做一部分题就结束 | 未提交的题在 `report` 时一律按不通过计分，报告里列出未完成数 |
| 单题拖太久 | 每题有限时（`task.json` 的 `time_limit_min`）。超时提交照样判分，但记为不通过，并在报告中标出 |

剩余风险：模型主动去读 `~/.litmus/key` 并解密。这属于刻意作弊，个人工具不防到这个程度。

## 5. 评测维度与题量

全部题目都是手写的小型独立项目，Java 和 Python 大约各占一半。每题几百到一两千行代码，编译和跑测试都在秒级。题目的 bug 类型参照真实项目里的常见问题设计。

| 维度 | 标准题数 | 快速模式 | 参考榜单 | 判分 |
|---|---|---|---|---|
| 修 Bug | 12 | 3 | SWE-bench | 隐藏测试：原来失败的必须变成通过（F2P），原来通过的不能挂（P2P）+ 可合入性检查 |
| 新功能 / 跨文件改动 | 8 | 3 | FeatureBench | 隐藏测试 + 可合入性检查 |
| 终端实操 | 8 | 3 | Terminal-Bench | 检查脚本验证最终状态（生成的文件、内容、配置），只判过或不过 |
| 工具调用 | 8 | 3 | BFCL / τ-bench | 给定工具定义和场景，模型把调用写入 `answer.json`。按结构比对函数名和参数；包含"没有合适工具时应该不调用"的题 |
| 读代码 | 8 | 3 | RULER / MRCR | 在一个 3～5 千行的代码库里回答调用链、数据流问题，按固定格式写入 `answer.json`，归一化后精确匹配 |
| 小范围编辑 | 8 | 3 | Aider | 隐藏测试 + 改动行数不超过上限 + 不碰无关文件 |
| Code Review | 8 | 3 | — | 给一份含预埋问题的 diff，模型把发现写入 `review.json`（文件、行号、描述）。文件相同、行号相差 ±3 以内算命中，**命中全部预埋问题**才算通过 |
| **合计** | **60** | **21** | | |

**可合入性检查**（用于修 Bug、新功能两类），以下任一项不满足即判不通过：
- 只改了 `task.json` 里 `allowed_paths` 允许的文件
- 没有修改或删除已有测试
- 代码能编译（Java 用 `javac`，Python 用 `py_compile`）

报告里单独统计"单测通过但被可合入性否决"的题数。

**题目顺序固定**，所有模型都按同一顺序做题。后面的题会受前面上下文的影响，但对每个模型的影响相同。报告逐题记录序号和耗时，用户可以自己看出模型是否越做越慢、越做越差。

## 6. 报告内容

只列客观指标，不下结论、不做加权：

| 指标 | 来源 |
|---|---|
| 总分 = 通过题数 / 总题数（每题等权） | 脚本判分 |
| 各维度通过率 + 95% 置信区间（Wilson 区间） | 脚本判分 |
| 可合入性否决数、超时数、未完成数、跳过数 | 脚本记录 |
| Code Review 的额外条目数（预埋问题以外提出的意见，只列数字不判对错） | 脚本统计 |
| 每题耗时、总耗时 | `next` 到 `submit` 的时间差 |
| token 用量（输入 / 输出 / 缓存 / 思考）、模型 ID | 读工具本地会话日志，按"会话工作目录 = litmus 仓库"和时间窗口匹配。能按时间切分的就给逐题用量，否则只给总量；解析不了的标"未采集" |
| 工具名称、litmus 提交号、模式（标准 / 快速）、JDK / Python 版本、开始和结束时间 | `start` 时检测 |
| 成绩是否有效 | 防篡改校验结果 |

第一版要解析会话日志的工具：

| 工具 | 日志位置 |
|---|---|
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` |
| Claude Code | `~/.claude/projects/<编码后的路径>/*.jsonl` |
| OpenCode | `~/.local/share/opencode/` |

其他工具以后再补解析器，补之前 token 和模型 ID 标"未采集"，其余指标照常出。

不同模式（标准 / 快速）的题目集合不同，分数不能互相比较。报告头部会写明模式。

## 7. 目录结构

```
litmus/
├── litmus.py               # 入口，只用 Python 标准库
├── litmus/                 # 实现：流程状态、判分、加解密、报告、日志解析、环境检查
├── tasks/
│   ├── manifest.json       # 题目固定顺序、快速模式抽选的题
│   └── <题号>/
│       ├── task.json       # 维度、语言、标题、限时、allowed_paths、判分方式
│       ├── prompt.md       # 题面
│       ├── repo/           # 起始代码（含可见测试，供模型自测）
│       └── hidden.enc      # 加密：隐藏测试、参考答案、标准答案
├── docs/
├── runs/                   # 已忽略：每次测评的状态、工作目录、判分临时目录
└── reports/                # 已忽略：报告
```

- 题号格式：`<维度缩写>-<语言>-<序号>`，如 `bug-java-03`、`tool-py-02`。
- 出题时的明文隐藏部分放在 `tasks/<题号>/hidden/`，这个目录被 git 忽略；`seal` 后只提交 `hidden.enc`。
- 工作目录：`runs/<run-id>/work/<题号>/`；判分目录：`runs/<run-id>/grade/<题号>/`，判分时把模型的改动和解密出的隐藏测试合在一起执行。

## 8. 技术选择

| 项 | 选择 | 原因 |
|---|---|---|
| 实现语言 | Python 3.9+，只用标准库 | 任何机器拿来就能跑，不用 `pip install` |
| 配置格式 | JSON | 标准库自带 |
| 加密 | 系统 `openssl enc -aes-256-cbc -pbkdf2` | macOS / Linux 自带，避免引入第三方依赖 |
| Java 判分 | `javac` + `java`，自带一个单文件迷你测试运行器 | 不依赖 Maven 和网络，秒级出结果 |
| Python 判分 | 标准库 `unittest` | 不依赖 pytest |
| 运行环境要求 | Python 3.9+、JDK 17+、openssl | `start` 时检查，缺什么直接提示 |

## 9. 使用前提

- 工具必须能执行命令、能改文件（Agent 类工具）。纯网页聊天测不了。
- 测试期间关闭会把任务外派给别的模型的插件（`start` 会检测 ai-relay）。
- 工具的全局配置（全局 AGENTS.md / CLAUDE.md、技能、MCP）会影响结果，测的是"工具当前配置下的模型"。报告里记录工具名称，方便你自己对照。
- 密钥 `~/.litmus/key` 需要另外备份（比如存进密码管理器）；丢了就无法判分，只能重新出题加密。
